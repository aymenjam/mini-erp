# Spec 0.3 — Service template

- Roadmap item: 0.3
- Status: done. The GitLab pipeline is green.
- Depends on: 0.1, 0.2, ADR-004, ADR-006, `constitution.md`

## Goal
A small, working service skeleton that shows the hexagonal layout and proves the tool chain
(ArchUnit, Flyway, Testcontainers, resource-server security). Every new service is a copy of it.

## Scope
1. Maven module `services/service-template`, base package `org.j2ra.minierp.template`, with the layers
   `domain`, `application` (`port.in`, `port.out`), `infrastructure` (`in.rest`, `in.kafka`, `out.persistence`, `out.messaging`, `config`).
   It contains no business code. One `package-info.java` per package explains its role.
2. ArchUnit tests for the rules in `AGENTS.md`.
3. Flyway with one baseline migration `V1__baseline.sql` (no business table).
4. Integration test base class with Testcontainers PostgreSQL (image version equal to the compose file).
5. Spring Security as OAuth2 resource server: JWT validation, roles taken from `realm_access.roles` and mapped to `ROLE_<NAME>`.
   Public: `/actuator/health/**`. Everything else needs a valid token.
6. Error responses in Problem Details format (RFC 9457). Correlation id read from `X-Correlation-Id` and put in the log context.
7. Config by environment variables. Profile `dev` points to the dev infrastructure on `localhost` (database, Keycloak).
8. `docs/new-service.md`: the copy-and-rename steps for a new service.
9. Dockerfile for the service (multi-stage, Java 21 JRE, runs as non-root user).
10. An ADR "Baseline libraries" (roadmap 0.3) for every library, plugin and BOM used in 0.1 and here: the Spring Boot and
    Spring Cloud BOMs, the Spring Boot starters used, Flyway, PostgreSQL driver, ArchUnit, Testcontainers,
    spring-security-test, and the Maven Enforcer plugin (added in 0.1). Each entry has a one-line reason. No library without an ADR.
    Libraries that only spec 0.4 needs (gateway, Angular OIDC, frontend test tools) are covered by the ADRs of 0.4.
11. A Kafka client check, done once and written in the ADR (see AC-15). It is a throwaway run, not part of the template.

## Acceptance criteria
- AC-1: `./mvnw -B verify` builds the module and runs all its tests green, also in the GitLab pipeline (Docker available, see 0.1).
- AC-2: ArchUnit test: classes in `domain` depend on no Spring, JPA (`jakarta.persistence`), Kafka or `infrastructure` / `application` class.
- AC-3: ArchUnit test: `application` depends only on `domain` and on Java/Spring transaction annotations, never on `infrastructure`.
- AC-4: ArchUnit test: classes in `infrastructure.in` (REST, Kafka) depend on `application.port.in` and `domain` types only, not on `port.out` or `out.*`.
- AC-5: ArchUnit test: `@Transactional` is used only in `application`. `@Entity` only in `infrastructure.out.persistence`.
- AC-6: A test proves that the ArchUnit rules can fail: a deliberately wrong sample class (test sources only) is rejected by each rule.
- AC-7: The integration test starts the app against a PostgreSQL Testcontainer, Flyway applies `V1`, and `/actuator/health` returns `UP`.
- AC-8: Flyway `validate` is on. The app does not start if a migration file was changed after it was applied.
- AC-9: A test endpoint (test sources only) returns 401 without a token, 401 with an expired or wrongly signed token,
  403 with a token without the needed role, and 200 with the needed role.
- AC-10: Roles are read from `realm_access.roles`. A test shows `ROLE_SALES` is created for a token with role `SALES`.
- AC-11: An error response has `Content-Type: application/problem+json` and no stack trace.
- AC-12: The service starts with profile `dev` against the compose infrastructure, using only variables from `.env`.
- AC-13: The Docker image builds, starts, and answers `/actuator/health`. It does not run as root.
- AC-14: No secret is committed. All settings that differ per environment are environment variables.
- AC-15: Roadmap check "Kafka client 3.9 with broker 4.3". The `kafka-clients` version from the Spring Boot 3.5 BOM (3.9.x)
  is tested against the compose broker (4.3.x): a throwaway run creates a topic, produces and consumes with `localhost:9092`.
  The versions and the result are written in the ADR. The template keeps no Kafka dependency.
  If a problem is found, it is written in the spec before Phase 1.
- AC-16: `docs/new-service.md` lets a new service be created in under 15 minutes. Proof: `customers` is created from it in 0.4.
- AC-17: The ADR "Baseline libraries" exists in `docs/adr/` (next free number) and lists every library, plugin and BOM
  used in 0.1 and 0.3, including Maven Enforcer and the two BOMs, each with a one-line reason.

## Out of scope
- Any business logic, entities or endpoints (Phase 1).
- Kafka publishing, outbox table and consumers (Phase 1, item 1.4). Only the empty package layout exists.
- A Maven archetype or generator script.
- Shared library modules between services.
- Observability, resilience, contract tests (Phase 6).
- Method-level role rules for real endpoints (each feature spec defines them).

## Addendum 2026-09-21 (owner request)
Added after the first implementation, before the commit of 0.3.

### Scope
12. Lombok, limited: only `@Getter`, `@RequiredArgsConstructor`, `@Slf4j`, only in `infrastructure`, plus
    `@NoArgsConstructor(access = AccessLevel.PROTECTED)` only in `infrastructure.out.persistence` (JPA entities). Configured as an explicit annotation processor
    in the root POM (works with JDK 25 and JDK 21). Rules in `AGENTS.md`, library in ADR-008.
13. Explanations of the architecture: `package-info.java` with role / belongs here / must not be here, `docs/hexagonal-guide.md`,
    a naming table in `constitution.md` (section 8), trade-offs in ADR-006. Class comments stay short.

### Acceptance criteria
- AC-18: Lombok is forbidden in `domain` and `application`, allowed only for the annotations of scope item 12 (`@NoArgsConstructor` only in the protected form, only in
  `infrastructure.out.persistence`). Proof: `LombokUsageTest` and an ArchUnit rule
  on the real service, wrong samples in `archfixture` for each rule, and a compile error for every other Lombok feature (`lombok.config`).
  The build passes on JDK 25 and on JDK 21.
- AC-19: The documents of scope item 13 exist, and every path they mention exists.

## Addendum 2 2026-09-21 (owner request): API styles and API documentation
Added before the commit of 0.3. Decision: ADR-009. Library: springdoc (ADR-008).

### Scope
14. API styles: REST is the default. GraphQL is optional, per use case, and needs a short ADR each time. The template has only the empty package
    `infrastructure.in.graphql` (package-info). No GraphQL library, no schema.
15. OpenAPI documentation with springdoc-openapi `2.8.17` (the version for Boot 3.5; found on Maven Central, listed in ADR-008).
    `OpenApiConfig` in `infrastructure.config`: title from `spring.application.name`, Bearer JWT scheme, reusable responses 401, 403 and 500 as
    `application/problem+json`, added to every operation. Swagger UI and `/v3/api-docs` are off by default and on only with the profile `dev`.
    `SecurityConfig` opens their URLs only when they are on.
16. Two ArchUnit rules: R10 (GraphQL adapters call input ports only) and R11 (endpoint methods in `in.rest` have `@Operation`).
17. `docs/api-guide.md` and ADR-009 (with the REST and GraphQL comparison). Links from `AGENTS.md`, `docs/new-service.md`, `README.md`.

### Acceptance criteria
- AC-20: With the profile `dev`, `/v3/api-docs` is open and valid OpenAPI 3 (title = application name). It has the Bearer JWT scheme, and 401, 403 and 500
  as reusable `application/problem+json` responses that the operations refer to. Swagger UI is open. Proof: `ApiDocsDevProfileTest`.
- AC-21: R10 rejects a GraphQL adapter that uses an output port, a use case class or an outbound adapter. Proof: `ArchitectureRulesCanFailTest` and fixture `archfixture/r10`.
- AC-22: Without the profile `dev`, `/v3/api-docs`, `/swagger-ui.html` and the UI page are refused: 401 without a token (security), 404 with a valid token
  (springdoc off). Proof: `ApiDocsOffByDefaultTest`.
- AC-23: R11 rejects each endpoint method (`@GetMapping`, `@PostMapping`, `@PutMapping`, `@PatchMapping`, `@DeleteMapping`) in `in.rest` without `@Operation`,
  and does not report a documented one. Proof: `ArchitectureRulesCanFailTest` and fixture `archfixture/r11`.
- AC-24: `docs/api-guide.md` and ADR-009 exist, are linked from `AGENTS.md` and `docs/new-service.md`, and every path they mention exists.
  The template has no `spring-graphql` dependency and no `.graphqls` file.

### Out of scope
- A GraphQL dependency or schema. Swagger UI behind the gateway (roadmap 0.4). Documenting real endpoints (Phase 1).
- `@RequestMapping` on a method (R11 checks the five verb annotations only).
