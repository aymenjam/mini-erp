## Goal
One Maven multi-module build and a basic GitLab pipeline, so that every later service starts from a working,
reproducible build with pinned versions.

## Scope
1. Root `pom.xml` (packaging `pom`): groupId `org.j2ra.minierp`, Java 21, UTF-8.
   - Imports the Spring Boot 3.5.16 BOM and the Spring Cloud 2025.0.3 BOM in `dependencyManagement`.
   - Pins plugin versions. Sets the compiler `release` to 21.
   - Adds the Maven Enforcer plugin (Java 21 rule). The "Baseline libraries" ADR does not exist yet (it is written in 0.3),
     so the owner approves this plugin before it is added (`AGENTS.md`, "Do not"). Spec 0.3 then lists it in the ADR,
     together with the two BOMs.
   - Lists modules under `services/`. It may have no module yet: services arrive in 0.3 and 0.4.
2. Maven wrapper (`mvnw`, `mvnw.cmd`, `.mvn/wrapper/`) pinned to a Maven 3.9.x version.
3. `.gitlab-ci.yml` for the personal GitLab project, with these stages:
   - `docker-check`: fails early with a clear message when Docker is not reachable.
   - `build`: `./mvnw -B verify` on Java 21 (image `maven:3.9-eclipse-temurin-21`).
   - Maven cache for the local repository, kept between jobs and between pipelines.
   - Test reports (JUnit XML) shown in GitLab.
4. Docker access for Testcontainers in the pipeline (see the criteria below). Supported setups:
   - **GitLab.com shared runners or a runner with the Docker executor:** service `docker:dind`, privileged runner,
     variables `DOCKER_HOST=tcp://docker:2375`, `DOCKER_TLS_CERTDIR=""`, and `TESTCONTAINERS_HOST_OVERRIDE=docker`.
   - **Self-managed runner with the Docker socket mounted** (`/var/run/docker.sock`): no dind, no `DOCKER_HOST`.
5. A short "Build and CI" section in `README.md`: how to build locally, and how to set up a runner with Docker.

## Acceptance criteria
- AC-1: `./mvnw -B verify` succeeds on a clean clone with Java 21 and no local Maven installed.
- AC-2: The root POM imports the Boot 3.5.16 and Spring Cloud 2025.0.3 BOMs. Versions are exact, no ranges, no `LATEST`.
- AC-3: The build fails if the Java version is lower than 21 (Maven Enforcer rule). This AC checks the build rule only.
  The ADR entry for the plugin is checked in spec 0.3 (AC-17).
- AC-4: `.gitlab-ci.yml` runs on every push and merge request. The `build` job runs `./mvnw -B verify`.
- AC-5: The `docker-check` job runs `docker info` and, on failure, prints which setup is expected (dind or socket) and stops the pipeline.
- AC-6: Docker access for Testcontainers is documented in `README.md`: the two setups, the variables above, and the fact that the
  dind runner must be privileged.
- AC-7: Maven cache is configured, and the second pipeline run downloads far fewer dependencies than the first (check in the job log).
- AC-8: JUnit reports appear in the GitLab merge request view.
- AC-9: `.gitignore` keeps `target/`, `.idea/`, `*.iml`, `.env` and `node_modules/` out of Git. `git status` is clean after a full build.
- AC-10: No secret in the repo or in `.gitlab-ci.yml`. Secrets come from GitLab CI/CD variables.

## Out of scope
- Deployment, container registry, release or tag jobs (roadmap 6.4).
- Building Docker images of services (with each service in 0.3 / 0.4).
- Frontend jobs (added in 0.4).
- Dependency and container vulnerability scanning (roadmap item 1.5, with a small ADR; needed because of
  "Decision: Spring Boot 3.5" in `constitution.md`).
- Path-based pipelines (only when the build becomes slow).
- Kubernetes and Helm.
